## 自动检查状态

- `npm run check`：本轮严格 TypeScript 检查、48 项 Vitest 测试和 Vite 生产构建通过。
- `npm run format:check`：通过。正常 HTTP 入口返回 200；Node 使用系统证书库校验 HTTPS 后返回 200。本机 curl／PowerShell 的 Schannel 请求出现握手失败，未据此改动系统 TLS 设置；真实 Office WebView 的验证记录见上表。
- 48 项包括原有 24 项和本轮新增 24 项适配器回归测试。
- 新增覆盖：WPS 独立范围恢复、过期选区、只读／保护文档、后续修改冲突、跨文档误写；Office 只读快照身份与查询执行。
- 回归测试发现的 WPS 跨文档写入问题已修复：写入前再次核对文档身份与 Range 归属，对应测试通过。
- Vite 已忽略 `output/` 和 `.local/` 文件监听，避免 Office 保存时锁定临时文件导致服务退出。正常运行时未启用测试令牌，诊断入口不会执行测试写入。
- `npm run validate:office`：微软清单校验通过；这不等于商店审核或跨平台实机验收。初始 XML 解析与本地静态入口 HTTP 200 检查也通过。

宿主替身测试验证边界行为，不能替代真实客户端操作与安装验收。

## v0.2.0 便携版验收

便携版采用独立注册项、WPS HTTP 18765 和 Office HTTPS 18766，以下结果与上方开发接入记录分开。

- `npm run test:portable`：2 项静态服务、12 组证书生命周期、12 项控制器测试，共 26 项通过。控制器测试隔离真实注册表、宿主进程与用户目录；证书单元测试使用内存信任存储。
- 新增便携启动回归检查：捕获并验证 Word／Excel 所用程序、带引号的试用文件路径和正常显示模式。控制器使用模拟启动器，因此该检查不等于本机真实 Office 画面验收。
- 本轮源码检查：49 项单元测试、严格类型检查和 Vite 构建通过。
- 本轮本地指令解析支持为文字放大指定 8–72 磅字号，并对越界、缺失数值和不支持的单位提出澄清；测试覆盖“把字放大到30”及上述边界。该能力尚未在四个宿主的真实文档中验收；加粗、居中、行距、缩进及新增 Excel 操作仍未实现。
- 原生启动器 `--smoke-wps`：在包含中文和空格的解压路径中，实际 EXE 启动本地 HTTP 服务、健康检查和停止流程通过。这项检查不是 WPS 任务窗格全部操作的验收。
- 独立临时状态目录中的证书创建、当前用户信任、强制续期、旧指纹清理和移除实测通过；Windows 信任提示由用户确认。未修改微软共享开发 CA。
- 已修正 Windows 证书命令的时间参数：按 UTC 计算时限后转本地时间，避免香港时区下少 8 小时。修正后无 Root 信任的独立签发及 HTTPS 校验通过，签发后测得剩余 29.999988 天，符合 30 天有效期。
- HTTPS 测试显式使用刚签发的证书作为信任依据，保持证书验证开启；`localhost`、`127.0.0.1`、`::1` 访问及服务停止后端口释放通过。这不等同于 Office WebView 的新一轮验收。

本机持久启用便携版 Office 的验收未执行：自动审批将授权理解为临时证书测试，拒绝了持久配置操作；未绕过该限制。Office 首次启用留给用户通过启动器完成，便携版完整 Office 界面端到端流程仍待实测。

构建产物为 `output/portable/OfficeHelper-0.2.0-win-x64.zip`。最终 ZIP 在中文与空格路径解压、子进程 PATH 仅含 Windows 系统目录（没有 Node/npm）时，实际 EXE 启动、健康检查与停止通过。压缩包内 41 个文件，扫描未发现私钥、开发源码或诊断入口；便携 Office 清单通过微软校验。当前 EXE 未签名，自动更新和商店发布未完成。
