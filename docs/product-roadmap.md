# 面向不熟悉电脑的中老年人的功能路线图

研究日期：2026-11-26。本文是产品建议与验收计划，不是已发布功能清单。

产品形态为 WPS 文字／表格和 Microsoft Word／Excel 内的侧边栏插件。用户打开自己的办公文件后，通过几个直白的任务按钮完成操作；浏览器页面用于开发预览。首批重点是让用户能独立完成小任务，并知道处理了哪里、结果在哪里、做错后怎样恢复。

## 事实、假设与当前进度

以下三类信息分开判断：

- **用户已明确的需求**：服务不熟悉电脑的中老年人，采用插件形式，同时考虑 WPS 和 Microsoft Office；框架应便于以后增加、更改功能。
- **来源支持的事实**：年龄相关的视觉、精细操作和注意力变化可能影响界面使用；打印缩放、求和和删除重复数据有具体行为与限制，见文末官方资料。
- **尚待验证的产品假设**：放大文字、合计、整理表格、打印和找回保存文件，是这批目标用户的重要任务；大按钮和逐步预览能够提高独立完成率。目前没有访谈或使用数据证明其频率和排序。

截至本文整理时，已有注册式功能模块、统一宿主适配层、能力检查、预览后确认、选区快照，以及单步恢复机制。自然语言入口为本地短语匹配。

## 首批八项能力

P0 是第一轮可用性试验必需项；P1 在 P0 测试后按真实需求选择；P2 延后验证。优先级表示顺序，不代表已承诺的交付日期。

| 优先级 | 用户看到的功能                   | 场景与最小范围                                                                                           | 核心验收条件                                                                                                                                                             |
| ------ | -------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P0     | **看看要改哪里／恢复刚才的修改** | 用户在两个文档间切换，或担心选错内容。预览显示文档名、工作表／文字片段、处理范围；每次修改后给出恢复入口 | 确认前换文件、换选区或修改目标内容，旧预览不能继续写入；取消无变化；恢复只恢复本次允许恢复的修改，不覆盖用户后续编辑；无恢复能力时事前说明                               |
| P0     | **把字放大**                     | 通知、说明等文字太小。先支持选中且字号一致的一段文字；显示原字号和目标字号                               | 文字内容、未选中文字不变；混合字号、只读和空选区给出下一步；真实宿主完成“放大—确认效果—恢复”；说明字号修改可能改变分页。仅放大屏幕显示的“看大一点”作为独立候选，避免混淆 |
| P0     | **算一下合计**                   | 报销清单、活动费用中选中金额并查看总数。首版只报告结果；文本、空白、错误值分别解释                       | 120、85、45.5、200 得到 450.5；文本 `"100"` 不悄悄转数字；含错误值时明确提示结果不完整；说明是否包含隐藏／筛选行，无法可靠判断时阻止该情形的计算；不写入或覆盖单元格     |
| P1     | **让表格看清楚**                 | 名单中名字显示不全、标题看不清。提供列宽适配、自动换行、表头强调三个可分别选择的动作                     | 每个动作先展示范围；值、公式、行顺序不变；合并单元格和保护区域被识别并给出处理建议；恢复列宽、换行与格式；不自动把编号、手机号转换成数值                                 |
| P1     | **打印前检查**                   | 费用表打印时少了一列，或缩成一张后看不清。先做 Excel／WPS 表格的打印范围、横向纸张、宽度一页方案         | 展示范围、方向和可验证的分页信息；默认高度自动，允许多页；在原生打印预览确认无漏列；过度缩小时提示调整；最后由用户在原生打印界面提交打印                                 |
| P1     | **另存一份／保存成 PDF**         | 交材料前保留原稿，导出后找不到文件。先明确保存范围、文件名和目标文件夹                                   | 原件不被覆盖；重名时选择新名称或交给原生确认；取消、失败不显示“已保存”；成功后能打开结果或定位文件夹，并展示真实保存位置；文档／工作表范围明确                           |
| P1     | **找出重复和漏填**               | 活动报名表中有人重复登记、必填项为空。用户明确选择判断列与必填列，助手先列出待核对行                     | 同名不同联系方式不会默认判为同一人；说明是否忽略首尾空格、大小写；结果能定位原始行；首版不删除、不排序；空白是否有问题由用户选定的必填列决定                             |
| P2     | **按提示做一份通知**             | 偶尔要写活动通知，难以从空白页开始。提供经过验证的固定模板，逐项填写标题、时间、地点、正文和联系人       | 未填信息可见且不编造；修改预览后再生成新文档；已有文档不被替换；首版模板生成无需模型；只有用户试验确认需求后再增加润色或语音入口                                         |

求和当前契约只有普通单元格值，完善错误类别和隐藏／筛选行提示需要扩展宿主快照，不能仅改提示文案。保存、打印、复杂格式等能力也要逐项探测宿主接口；没有可靠接口时提供对应版本的操作指引，并明确这一步需要用户在原软件完成。

## 共同的操作体验

**每次只解释当前一步。** 首页根据文字或表格显示适用按钮，首屏建议不超过四项，其余收进“更多”。选范围、预览、执行、结果采用固定位置；只读查询可以直接给结果，实际修改必须先展示会改变什么。

**用结果语言命名。** “算一下合计”“把字放大”“恢复刚才的修改”比“执行工具”“撤销事务”更容易核对。空选区提示“先在文档里选中要处理的文字”，并给简短示意；不要求用户理解单元格 API、证书、模型或提示词。

**界面自身先看得清、点得准。** 产品建议主要按钮至少 44×44 CSS 像素、正文默认 18 CSS 像素、支持键盘和清楚的焦点状态；状态同时使用文字和图形，不能只靠红绿区别。在侧边栏变窄、系统缩放 150%／200% 时检查按钮与正文不被遮挡。44 像素是本产品采用的设计目标；WCAG 2.2 AA 的目标尺寸条款为至少 24×24 CSS 像素且有例外，不能将两者混为一谈。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

**错误要给可做的下一步。** 区分“未选内容”“当前文件只读”“此版本暂不支持”“文件已关闭”“连接失败”；不展示原始异常作为主要文案。进行中防止重复提交；失败后保留用户输入。文档已被另行修改、恢复信息过期时，停止自动恢复并解释原因。

**安装体验单独验收。** 试用前由协助者完成一次安装，日常入口固定在办公软件中；后续验证重新启动软件后能再次找到助手。当前开发服务器、开发证书和调试清单属于接入验证阶段，不能当成面向长辈的成品安装方式。

## 开发顺序与交付门槛

1. **接入与恢复闭环。** 四个宿主的最小验证已完成，继续补充复杂文件、保护状态、多窗口和原生撤销等实机场景。按实际安装版本和验证结果标明支持范围，未覆盖的版本不承诺兼容。
2. **完成 P0 的真实文件试用版。** 收紧求和对非数字、错误、隐藏行的说明，完善字号预览与选区过期保护。先用专门测试文件验证空选区、只读、切换文档、重复点击和恢复冲突，再开展下述五人试验。
3. **按访谈结果选两项 P1。** 默认候选为“让表格看清楚”和“打印前检查”，但保存／找文件若是主要障碍，就前移“另存一份”。每项同时实现一个清楚的失败路径和相应恢复方式，逐宿主发布。
4. **增加核对工具和模板。** 确认用户能理解范围后，再推进重复／漏填检查。模板、语音和自由描述需求进入下一轮小样本验证，避免提前引入难以核对的复杂生成操作。

新增能力继续沿用“功能定义 → 确定性计划 → 宿主适配器”的结构。每个功能声明适用文件类型、所需能力、输入校验和恢复策略；界面只负责输入与展示，Office／WPS 对象不进入功能业务代码。需要新增动作时，先补契约和能力检测，再分别实现适配器，避免在按钮组件中堆积宿主分支。

保存文件、发起打印等操作并不具备与格式修改相同的撤销语义：保存前说明新文件位置；打印前停在预览；不能用统一的“恢复成功”掩盖不可恢复的外部结果。

## 五位目标用户的验证计划

这是下一步待执行的研究计划，尚未招募或完成测试。五人的结果用于发现障碍，不用于推断全部中老年人的偏好或成功率。

**招募方式：** 找五位自述不熟悉电脑、近期确实用过办公文件的人，尽量包含两位 WPS 常用者、两位 Office 常用者和一位两者都用的人；覆盖至少两位 60 岁以上参与者。记录平时任务、视力／输入偏好及每周使用频率，以实际操作能力判断是否属于目标群体，不仅按年龄筛选。每位使用自己熟悉的软件。

**每场 35–45 分钟：** 先用 5–10 分钟询问最近一次困难及如何求助，再完成 20–25 分钟任务，最后回顾。使用虚构名单、金额和通知，不要求上传真实个人资料。先安排一次普通软件操作作为基线，再换同难度文件使用插件；两组任务顺序交替，以减少学习顺序影响。录屏须征得参与者同意。

| 任务               | 给参与者的目标描述                                     | 观察与通过条件                                                             |
| ------------------ | ------------------------------------------------------ | -------------------------------------------------------------------------- |
| 找到助手并判断范围 | “请打开这份通知，把第二段处理一下，先看看会改到哪里。” | 60 秒内找到入口；能说出当前文件和目标段落；不由主持人指出按钮              |
| 放大与恢复         | “这段字有点小，请让它大一些；现在想回到刚才的样子。”   | 3 分钟内完成；仅目标段落改变；能在 30 秒内找到恢复入口并确认恢复           |
| 合计并解释异常     | “看看这几笔费用共多少，其中一格可能填写得不一样。”     | 3 分钟内得到正确数字小计；发现文本金额没有计入；不把不完整小计当作全部费用 |
| 选区变化           | 给出预览后，让参与者切换另一个文件，再尝试继续         | 系统拒绝旧任务；参与者明白需要重新选择；无误写                             |
| 下一轮 P1 候选     | 通过简单原型体验“完整打印这张名单”或“另存一份并找到它” | 能理解范围、预期结果和最后一步；原型结果单独记录，不算成真实功能完成       |

每次记录独立完成／口头提示后完成／演示后完成／未完成，另记耗时、误点击、求助次数和用户自己的表述。“很喜欢”不能替代是否正确完成。主持人先观察，不教按钮位置；用户明确卡住时可以帮助，但应标为辅助完成。

**第一轮门槛：** 五人中至少四人独立完成字号修改、恢复和普通合计；所有参与者都能察觉异常金额未计入，或系统明确阻止把结果当作完整合计；错误文件写入、无提示覆盖和错误恢复必须为零。任何一人被关键提示误导，都需要分析原因并修改，不因达到四人通过而忽略。

修改后邀请原参与者复测失败任务，并尽量增加两位未接触原型的人，区分设计改进与记忆学习。五人试验不能代替版本兼容性和真实打印／导出文件的验收。
